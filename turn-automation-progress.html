Scheduling rules tightened across every region July 27
Never today or tomorrow — new turn work is placed at least 3 days out so the crew always gets notice. Available dates only move closer, never out. Longest-vacant units are prioritised ahead of higher-rent ones. And when a turn finishes early, forward-compaction pulls later turns' work into the freed capacity (forward only — nothing is ever pushed later).
✓
Rent Ready is now verified, not assumed Aug 3
A unit can show "Rent Ready = Yes" either because it was genuinely turned or because the data is stale — so the automation now has to prove a unit wasn't turned before changing the flag, using a final walkthrough completed after the move-out. Two blind spots were found and fixed: units with no turn scheduled yet were skipped entirely by the check (the riskiest case), and completion was being read from a feed that only contains open turns, which made fully-turned units look untouched. A standing audit now reports both problems across all three regions.

The turn pipeline

Each stage a turn goes through, from a resident giving notice to the unit being ready to rent.

1
Detect move-outs & notices
Local daily run

Done

  • Reads AppFolio vacancy daily; finds units that moved out or gave notice — all three regions: Spokane, Tacoma, Tri-Cities
  • Turn start date = move-out + 1 day
  • 100% AppFolio ↔ PropertyMeld unit matching

To finish

  • Runs as part of your schedule spokane turns command — not yet a cloud cron (see Next Steps #1)
2
Create the turn project
Local daily run

Done

  • Creates the "Standard Unit Turn" (7-meld template) in PropertyMeld for any unit missing one
  • Skips units that already have an open turn; skips rent-ready units
  • Runs for all three regions (Spokane, Tacoma, Tri-Cities) — onboarded July 20

To finish

  • Uses only PropertyMeld + AppFolio APIs (no 2FA) — ready to move to the cloud so it runs hands-off (Next Steps #1)
3
Dedupe duplicate turns
Automated · cloud

Done

  • If a unit has more than one open turn, keeps the canonical one and neutralizes the duplicate
  • Runs first in the daily cloud job — stops double-booking at the source

To finish

  • Nothing — complete
4
Schedule in-house work
Automated · cloud · all 3 regions

Done

  • All three regions now auto-schedule — Spokane (Ron & Magoon, 6:20 AM), Tri-Cities (James & Ryan for paint/maint, Margarito for walkthroughs, 6:40 AM), Tacoma (Armani does all of it, 7:00 AM)
  • 2 paint days + 1 maintenance day per turn, same tech (Tacoma: 2 paint + 2 maintenance) + 1-hr initial walkthrough
  • Mon–Thu 8a–4p, densely packed, never double-books
  • Append-only — never moves work already on the calendar; forward-compaction pulls later work earlier when a turn finishes early (forward only)
  • Priority: leased → Converted → Converting → days vacant → rent
  • Never books today or tomorrow — 3 days' lead time minimum

To finish

  • Thin crews — near-term calendars fill fast, so new turns can still land weeks out (Tacoma is a single tech)
  • Forward-compaction isn't wired for Tacoma yet — it assumes the 2+1 day pattern (Next Steps #5)
5

  • Runs daily in each region's cloud job
  • A completed final walkthrough is the system's proof a unit was actually turned — it's what the Rent Ready check tests against

To finish

Set AppFolio available date & Rent Ready
Local · cloud blocked · all 3 regions

Done

Next steps

In priority order.

1
Move turn detection & creation to the cloud High
Stages 1–2 use only PropertyMeld/AppFolio APIs (no 2FA), so they can run hands-off in the daily cloud job. Then the only thing needing your local run is the AppFolio date write.
2
Activate cancelled-move-out cleanup High
Run the built script as a cloud dry-run, review the flagged turns, then add it as the first step of the daily workflow so cancelled turns are removed and their slots backfilled automatically.
3
Automate vendor scheduling Medium
Capture the PropertyMeld vendor assign/schedule API, then auto-book cleaning → carpet → flooring. This also lets the final walkthrough land on an exact date instead of a suggestion.
4
Get the AppFolio date write into the cloud Medium
Resolve the SMS-2FA blocker (trusted device / app token), or formalize it as the one daily local click. Until then Stage 7 stays local.
5
Extend forward-compaction to Tacoma Medium
Compaction currently assumes the 2-paint + 1-maintenance day pattern, so it isn't wired for Tacoma's 2 + 2. Until it is, an early Tacoma finish doesn't pull later turns forward — capacity is left idle on a single-tech region where it matters most.
6
Catch missed turns automatically High
Two units sat vacant for days with no turn project at all (tc68 #D096, tc34 #A103) — detection can miss a unit and the failure is silent. The standing audit finds them now, but it's run by hand; it should run daily and alert instead of waiting for someone to spot a wrong Rent Ready flag.
7
Cover the properties no region owns Later
A few properties sit outside every region's city list — Helena (hl73) surfaced this way with a stale Rent Ready flag and no automation watching it. Either assign these to a region or give them a catch-all pass.
8
Backlog cleanup Later
Cancel stale / duplicate open turns and mark finished-but-still-open turns complete so counts and the calendar stay clean.
